# Talo CLI 연결·설정 UI 기획서 v0.1

작성일: 2026-09-03  
범위: 터미널에서의 첫 설정, AI 연결, 모델 선택, 연결 관리, 오류 복구  
상태: 구현 전 UI 기획. 화면의 이름·선택지·동작은 설계안이다.

## 1. 제품 목표

사용자가 `talo`를 실행하고 화면에서 선택하는 것만으로 개발을 시작하게 한다. 기본 연결 과정에서 base URL, API 프로토콜, 환경변수 이름, 내부 모델 ID, 키체인 계정명을 직접 조합하지 않게 한다.

첫 설정의 목표 경험:

> Talo 실행 → 사용할 AI 선택 → 로그인 또는 키 붙여넣기 → 모델 선택 → 작업 시작

연결 이후의 목표 경험:

> Talo 실행 → 작업 요청

모델을 바꾸는 목표 경험:

> `/model` → 검색·선택 → 작업 이어가기

설치된 코딩 도구를 연결하는 경우도 Talo 안에서 지원 여부와 다음 행동을 안내한다. 사용자를 설명문과 셸 명령 목록으로 돌려보내지 않는다.

## 2. 현재 안내에서 바꿀 점

사용자가 제시한 안내를 UX 문제의 근거로 삼았다. 안내에 나온 머신 환경변수·설치 프로그램·지원 모델·Talo 구현 상태는 이번 작업에서 직접 확인하지 않았다.

| 현재 안내의 문제 | 바꿀 경험 |
| --- | --- |
| 긴 connect add 명령을 직접 작성 | `talo connect` 선택형 화면 |
| 공급자마다 주소를 찾아 입력 | 검증된 서비스 프리셋으로 자동 설정 |
| 환경변수 이름과 저장 방법을 먼저 결정 | 키 붙여넣기, OS 보안 저장소 기본 사용 |
| 모델 ID를 정확히 알아야 함 | 계정에서 확인한 모델 목록 검색·선택 |
| 설정 저장 후 validate·use를 별도 실행 | 연결 확인·모델 선택·활성화를 한 흐름으로 처리 |
| API와 코딩 도구를 같은 provider처럼 설명 | 서비스 API 연결과 기존 코딩 도구 연결을 명확히 구분 |
| 미지원 연결을 다른 API로 대체해 같은 도구처럼 표기 | 원래 연결은 미지원 표시, 다른 방식은 별도 선택 |
| 오류 발생 시 긴 원문과 명령어 안내 | 실패한 단계에 맞는 버튼·메뉴 제공 |
| 기본 모델로 자동 라우팅 모델 제시 | 사용자가 선택한 구체적인 모델 유지 |

특히 `provider=codex`라는 이름으로 일반 OpenAI API를 등록해도 그것이 Codex CLI 연결이 되는 것은 아니다. UI의 연결 이름과 실제 동작이 일치해야 한다.

## 3. Hermes 참고 기준

2026-08-31 공개된 Hermes v0.21.0 릴리스에서 검색형 모델 선택기, 명령 팔레트, 연결 상태를 파악할 수 있는 상태 표시를 참고했다. 같은 릴리스의 아키텍처 자료에서 대화형 설정과 모델 전환을 별도 CLI 구성 요소로 둔 점도 참고했다. [공식 릴리스](https://github.com/NousResearch/hermes-agent/releases/tag/v2026.8.31), [해당 버전 아키텍처](https://github.com/NousResearch/hermes-agent/blob/v2026.8.31/website/docs/developer-guide/architecture.md)

이 문서는 Hermes의 실제 화면을 캡처해 복제한 결과가 아니다. 확인된 선택형 조작 패턴을 Talo의 사용자 흐름으로 구체화한 기획이다. 최신 setup.py와 model_switch.py 원문 추가 확인은 완료하지 못했으며, 해당 파일의 세부 동작을 확인했다고 주장하지 않는다.

## 4. UI 원칙

1. 선택 가능한 항목은 방향키·Enter로 조작한다.
2. 첫 화면에는 사용 가능한 연결과 가장 가까운 다음 행동을 먼저 보여준다.
3. 주소·인증 참조·프로토콜은 기본 흐름에서 자동 결정한다.
4. 비밀값을 입력받아도 셸 명령으로 다시 출력하지 않는다.
5. 로그인 성공, 모델 접근 성공, 코딩 도구 사용 가능을 구분한다.
6. 연결 실패 시 기존 연결과 선택 모델을 유지한다.
7. 뒤로 가면 안전한 입력·선택 상태를 유지한다.
8. 설정을 바꾸는 동안에도 현재 작업과 프로젝트를 잃지 않는다.
9. 모델 전환은 사용자 선택으로만 수행한다.
10. 실제 사용할 수 없는 기능을 활성 메뉴처럼 보여주지 않는다.

## 5. 진입점과 명령 정리

| 입력 | 기대 동작 |
| --- | --- |
| `talo` | 정상 연결이 있으면 대화 시작, 없으면 첫 연결 안내 |
| `talo setup` | AI 연결·기본 설정을 순서대로 다시 설정 |
| `talo connect` | 연결 목록·추가·재연결·해제 화면 |
| `talo model` | 기본 모델 선택 화면 |
| 대화 중 `/connect` | 연결 화면을 열고 완료 후 대화 복귀 |
| 대화 중 `/model` | 현재 작업 모델 선택 |
| 대화 중 `/settings` | 설정 화면 |
| `talo doctor` | 연결·설정·설치 상태를 점검하고 해결 동작 안내 |

기존 고급 명령이 구현돼 있다면 유지한다. `talo connect list`는 목록 별칭으로 받아들이도록 제안한다. 무인 실행에서는 별도 비대화형 옵션을 유지하되 일반 사용자 도움말은 선택형 화면을 먼저 소개한다. 이 표는 목표 동작이며 현재 명령 구현 여부는 미확인이다.

## 6. 화면 구성 규칙

| 영역 | 역할 |
| --- | --- |
| 상단 | Talo, 현재 프로젝트, 설정 제목 |
| 단계 표시 | 서비스 선택·연결·모델 선택 중 현재 단계 |
| 본문 | 짧은 질문, 선택 목록 또는 입력 하나 |
| 보조 설명 | 현재 선택한 항목의 특징·연결 상태 |
| 하단 | Enter 선택, Esc 뒤로, 검색 안내 |

글자색만으로 성공·실패를 표현하지 않는다. ‘연결됨’, ‘로그인 필요’, ‘사용 불가’ 같은 문구를 함께 표시한다. 한글 조합 입력 중 Enter가 의도치 않게 다음 단계로 넘어가지 않도록 검수한다.

대화형 화면은 80열을 기본으로 설계하고 좁은 터미널에서는 보조 설명을 다음 줄로 배치한다. 화면 읽기 도구와 단순 터미널을 위해 숫자 선택형 순차 질문 모드도 제공한다. ASCII 테두리·큰 로고가 내용과 입력 공간을 차지하지 않도록 한다.

이하 화면은 구현용 문구와 선택 구조를 나타내는 텍스트 시안이다. 실측 스크린샷이 아니다.

## 7. 첫 실행 화면

### S01. 사용할 연결이 없음

표시 문구:

> Talo에 사용할 AI를 연결하세요.  
> 연결하면 이 프로젝트에서 바로 작업할 수 있습니다.

선택지:

| 순서 | 문구 | 동작 |
| --- | --- | --- |
| 1 | AI 연결하기 | S02로 이동 |
| 2 | 기존 연결 찾기 | S04로 이동 |
| 3 | 나중에 하기 | 기록 열람·도움말이 가능한 대화 화면 |

처음부터 개인비서·개발자 버전을 선택하게 하지 않는다. 현재 제품은 개발자용 Talo다. 연결과 무관한 취향·테마·권한 세부 질문도 첫 시작 전에 필수로 묻지 않는다.

### S02. 연결 방식 선택

질문:

> 어떤 방식으로 연결할까요?

| 선택지 | 짧은 설명 | 노출 조건 |
| --- | --- | --- |
| AI 서비스 연결 | 로그인하거나 API 키를 입력합니다 | 항상 |
| 설치된 코딩 도구 연결 | 이 컴퓨터의 도구로 작업합니다 | 검증된 도구 어댑터가 하나 이상 있을 때 |
| 로컬 AI 연결 | 이 컴퓨터에서 실행 중인 모델을 사용합니다 | 로컬 연결 기능 지원 시 |
| 직접 설정 | 사용자 지정 서버를 연결합니다 | 고급 항목 |

API 연결만 구현된 첫 배포라면 이 단계를 생략하고 서비스 목록으로 바로 이동한다. 설치된 도구 항목을 활성화한 채 실제로는 API 키만 요구하지 않는다.

### S03. 서비스 선택

질문:

> 사용할 AI 서비스를 선택하세요.

검색 가능한 목록을 제공한다. 예시 후보는 OpenRouter, OpenAI API, Anthropic API, Google AI, DeepSeek다. 실제 출시 목록에는 연결 어댑터와 인증 방식 검증이 끝난 서비스만 포함한다.

각 행은 ‘서비스명 / 연결 상태’만 먼저 보여주고, 선택한 행의 보조 영역에 인증 방식과 필요한 정보를 표시한다.

예시:

| 항목 | 상태·설명 |
| --- | --- |
| DeepSeek | API 키로 연결 |
| OpenRouter | 연결된 계정에서 사용할 모델 선택 |
| OpenAI API | API 키로 연결 |
| 직접 설정 | 사용자 지정 주소 입력 |

지원 서비스의 base URL은 프리셋으로 설정한다. 사용자에게 기본 주소를 묻지 않는다. 주소를 수정하려면 ‘고급 설정’을 연다.

## 8. 기존 설정 활용

### S04. 기존 연결 찾기

이 기능은 사용자가 선택했을 때 실행한다. Talo에 저장된 연결, 공급자별로 명확히 식별되는 환경변수 존재 여부, 지원되는 도구의 공식 상태 확인을 대상으로 한다. 임의 폴더의 모든 .env와 다른 도구의 비밀 파일을 훑지 않는다.

발견 결과 예시:

| 발견 항목 | 표시 | 다음 행동 |
| --- | --- | --- |
| Talo 저장 연결 | DeepSeek · 저장된 연결 | 연결 확인 후 사용 |
| 공급자가 명확한 환경변수 | DeepSeek · 연결 정보 발견 | 이 설정 사용 |
| 이름이 일반적인 API_KEY | 공급자를 확인할 수 없는 키 발견 | 사용자가 서비스 선택 |
| 지원 도구 설치 | 도구명 · 설치 확인 | 공식 연결 상태 확인 |
| 미지원 도구 설치 | 도구명 · 연결 기능 준비 중 | 상세 설명만 제공 |

`API_KEY`, `BASE_URL`, `MODEL`이 있다는 이유만으로 특정 제품 연결이 검증됐다고 표시하지 않는다. 연결할 서비스·주소의 도메인과 출처를 보여주고 짝이 맞는지 확인한다. 값 자체는 마스킹한다.

현재 셸에서만 사용할 수 있는 환경변수를 택한 경우 ‘현재 환경에서 사용’으로 표시한다. 다음 실행에도 사용할 수 있게 보관하려면 보안 저장을 선택할 수 있다. 다른 도구의 로그인 토큰은 공식 지원 경로 없이 복사하지 않는다.

## 9. 인증 화면

### S05. 인증 방식

선택한 서비스에 지원 방식이 하나뿐이면 선택 단계를 생략한다.

| 방식 | 기본 문구 | 동작 |
| --- | --- | --- |
| 브라우저 로그인 | 브라우저에서 로그인 | 검증된 공식 인증 흐름 시작 |
| API 키 | API 키 붙여넣기 | S06 입력 화면 |
| 기존 연결 | 저장된 연결 사용 | 해당 자격 증명 참조로 검증 |

브라우저 로그인 메뉴는 Talo의 해당 연결에 실제로 지원될 때만 제공한다. 일반 API 연결을 계정 구독 로그인과 동일하게 표시하지 않는다.

### S06. API 키 입력

표시 문구:

> DeepSeek API 키를 붙여넣으세요.  
> 키는 이 Mac의 보안 저장소에 보관됩니다.

입력은 마스킹한다. 기본 동작은 OS 보안 저장소 저장이며, ‘이번 실행에서만 사용’은 보조 선택으로 둔다. 키체인을 사용할 수 없으면 이유를 짧게 표시하고 임시 사용 또는 저장 문제 해결을 제공한다. 평문 저장으로 자동 전환하지 않는다.

보조 동작:

- API 키 발급 페이지 열기: 검증된 서비스 공식 주소 사용.
- 다른 연결 방식: 지원되는 방식이 있을 때만 표시.
- 뒤로: 서비스 선택으로 돌아가기.

키를 붙여넣은 순간 바로 영구 저장하지 않는다. 연결 성공과 사용 선택 후 저장한다. 임시 보안 항목이 필요하면 취소·실패 시 정리한다. 입력한 비밀값을 로그·오류·클립보드 기록으로 다시 복사하지 않는다.

### S07. 브라우저 로그인

표시 문구:

> 브라우저에서 로그인을 완료하세요.  
> 완료되면 Talo로 자동으로 돌아옵니다.

보조 동작은 브라우저 다시 열기, 로그인 주소 확인, 취소다. 공식 흐름에 기기 코드가 필요한 경우에만 코드를 보여준다. 성공하면 계정 표시명 또는 식별 가능한 마스킹 정보와 연결 방식을 보여준다. 임의로 로그인 완료를 추정하지 않는다.

취소·만료·실패 시 S05로 돌아가며 현재 프로젝트와 작업은 유지한다. 로그인 뒤 추가 권한이 필요한 경우 서비스가 실제로 반환한 요구사항만 안내한다.

## 10. 연결 확인과 모델 선택

### S08. 연결 확인

진행 문구를 실제 단계에 맞춰 표시한다.

| 단계 | 문구 |
| --- | --- |
| 인증 확인 | 연결 정보를 확인하고 있습니다 |
| 모델 조회 | 사용할 수 있는 모델을 불러오고 있습니다 |
| 모델 접근 | 선택한 모델을 확인하고 있습니다 |
| 도구 호출 검증 | 코드 작업에 필요한 기능을 확인하고 있습니다 |

검증에서 실제 추론 요청이 필요하면 소량의 사용량이 발생할 수 있음을 시작 버튼 근처에 한 줄로 안내한다. 실제 저장소 내용은 연결 시험에 사용하지 않는다. 모의 도구의 호출 형식만 검사하고 파일 수정·셸 명령은 실행하지 않는다.

상태는 ‘계정 연결됨’, ‘모델 확인됨’, ‘코드 작업 사용 가능’으로 구분한다. 목록 조회 성공만으로 전체 기능 검증 완료를 표시하지 않는다.

### S09. 모델 선택

질문:

> 어떤 모델로 작업할까요?

| 화면 요소 | 동작 |
| --- | --- |
| 검색창 | 이름을 입력하면 즉시 필터링 |
| 최근 사용 | 최근에 사용한 유효한 모델 우선 표시 |
| 모델 목록 | 표시명·공급자·코드 작업 가능 여부 |
| 상세 영역 | 확인 가능한 입력 한도·가격 정보·검증 상태 |
| 직접 입력 | 목록 조회가 불가능할 때 고급 대안 |

실제 계정에서 조회한 모델과 검증된 카탈로그를 우선 사용한다. 특정 날짜의 모델명을 코드나 문서 예시에 고정해 그대로 추천하지 않는다. 서버에서 확인하지 못한 가격·한도·능력은 ‘확인되지 않음’으로 표시한다.

`openrouter/auto` 등 자동으로 모델을 고르는 항목은 기본 목록과 추천에서 제외한다. 사용자가 구체적인 모델을 직접 선택한다는 기존 제품 원칙을 유지한다. 공급자 내부 라우팅까지 Talo가 통제한다고 주장하지 않는다.

모델 목록 조회가 지원되지 않는 서비스에는 검증된 프리셋 목록을 제공하고 ‘서비스 목록을 실시간 확인할 수 없음’을 표시한다. 사용자가 API 문서를 읽어야만 다음으로 갈 수 있는 상황을 줄인다.

### S10. 완료

표시 예시:

> 연결되었습니다.  
> 서비스: DeepSeek  
> 모델: 선택한 모델  
> 코드 작업: 사용 가능

| 선택지 | 동작 |
| --- | --- |
| 이 모델로 시작 | 저장·활성화 후 대화 화면 |
| 다른 모델 선택 | S09로 돌아가기 |
| 연결 하나 더 추가 | 연결은 저장하고 S03으로 이동 |

추가로 validate나 use 명령을 실행할 필요가 없어야 한다. 내부 연결 ID는 자동 생성하고 기본 화면에 노출하지 않는다.

기존 기본 모델이 있는 사용자가 연결을 추가했다면 ‘이 모델로 전환’과 ‘추가만 하기’를 구분한다. 추가만 했는데 현재 작업 모델이 바뀌면 안 된다.

## 11. 기존 코딩 도구 연결

### S11. 설치된 도구 선택

사용자가 말한 Codex·AGY·DeepCode·OpenCode는 우선 도구 후보 목록이다. 이름만으로 같은 연결 방식을 가정하지 않는다. 해당 버전의 설치 여부와 Talo 어댑터 지원 상태를 각각 확인해야 한다.

| 실제 상태 | 표시 문구 | 행동 |
| --- | --- | --- |
| 어댑터 지원, 설치·로그인 확인 | 연결할 수 있습니다 | 선택 후 작업 연결 확인 |
| 어댑터 지원, 설치됨, 로그인 필요 | 로그인이 필요합니다 | 공식 로그인 시작 |
| 어댑터 지원, 미설치 | 설치가 필요합니다 | 설치 안내, 명시적 설치 선택 |
| 설치됐으나 어댑터 미지원 | 설치됨 · Talo 연결 준비 중 | 비활성 표시, 현재 한계 설명 |
| 설치 여부 확인 실패 | 설치 상태를 확인하지 못했습니다 | 다시 확인·경로 직접 지정 |

각 도구의 내부 API 키를 사용하는 것은 ‘해당 도구 연결’과 다르다. 사용자가 다른 방식도 원하면 ‘모델 API로 연결하기’를 별도 선택지로 제공하고 선택한 서비스 이름으로 저장한다.

화면 이름만 바꿔서는 이 흐름이 구현되지 않는다. 현재 실행부가 HTTP 모델 API만 지원한다면 코딩 도구 연결에는 별도 실행 어댑터가 필요하다. Codex의 특정 서버 명령, AGY의 로그인 방식, OpenCode 서버의 프로토콜을 이번 UI 문서에서 검증된 지원 기능으로 확정하지 않는다.

## 12. 대화 중 모델 전환

### S12. `/model`

현재 연결된 모델을 한 선택기에 모아 보여준다.

| 표시 | 행동 |
| --- | --- |
| 현재 모델 · 사용 중 | 선택 유지 |
| 다른 연결의 모델 · 사용 가능 | 전환 |
| 연결 만료 | 재연결 화면 |
| 새 AI 연결 | S03으로 이동 |

현재 세션의 전환은 다음 실행의 기본 모델 변경과 구분한다. 기본 모델로도 저장하고 싶으면 보조 동작으로 선택한다.

실행 중인 도구가 없으면 사용자 선택 직후 인계 자료를 준비하고 전환한다. 같은 전환에 재확인을 반복하지 않는다. 도구가 실행 중이라면 ‘완료 후 전환’ 또는 ‘중단하고 전환’을 제공한다. 중단 여부가 불명확하면 ‘실행 상태 확인 중’으로 남기고 새 모델이 같은 작업을 시작하지 않게 한다.

전환 완료 문구:

> 모델을 변경했습니다. 작업 목표와 변경 내용을 이어갑니다.

한도 초과 시 다른 모델을 자동 선택하지 않는다. ‘모델 선택’, ‘같은 모델 다시 시도’, ‘작업 저장 후 종료’를 제공한다. 로그인·연결 화면을 다녀와도 원래 세션으로 돌아온다.

## 13. 연결 관리·설정 화면

### S13. `talo connect` 또는 `/connect`

연결 목록에는 이름, 인증 방식, 마지막 확인 상태, 선택된 모델을 보여준다. 최근 확인 시각이 오래됐으면 실시간 상태처럼 표현하지 않는다.

항목 선택 후 제공할 동작:

| 동작 | 설명 |
| --- | --- |
| 사용하기 | 이 연결의 모델 선택 |
| 모델 변경 | 해당 연결의 모델 목록 |
| 다시 연결 | 인증 갱신 또는 키 변경 |
| 연결 확인 | 상태 재검사 |
| 이름 변경 | 사용자 표시명 변경 |
| 연결 해제 | Talo의 연결과 저장된 자격 증명 정리 |
| 고급 설정 | 주소·환경변수 참조·시간 제한 |

연결 해제는 현재 사용 중인 작업에 영향이 있으면 먼저 표시한다. Talo 연결을 해제하는 것이 외부 서비스 계정 삭제나 외부 토큰 폐기를 의미하지 않음을 필요한 경우 설명한다. 다른 Talo 연결이 같은 자격 증명을 참조하면 이를 확인한 뒤 저장 항목을 정리한다.

### S14. `/settings`

설정 항목은 AI 연결, 기본 모델, 작업 권한, 기억, 스킬, MCP 도구, 화면·언어, 진단으로 정리한다. 첫 버전에서 구현되지 않은 설정은 숨기거나 준비 중으로 표시한다.

AI 연결 화면 안에 기억·스킬·실행 권한 전체를 섞지 않는다. 연결 설정과 파일 실행 승인은 다른 작업이다.

### S15. 고급 설정

고급 사용자가 원하는 경우에만 다음을 보여준다.

- 사용자 지정 API 주소.
- API 형식: 설치된 어댑터가 지원하는 형식만 선택.
- 환경변수 참조와 사용 범위.
- 로컬 서버 주소·연결 시간 제한.
- 프록시 등 구현된 네트워크 설정.
- 민감값을 제거한 설정 보기.

기본 서비스 프리셋은 URL 경로를 일관되게 처리하고, 사용자가 `/chat/completions`를 붙여야 하는지 판단하게 하지 않는다. 사용자 지정 주소가 바뀌면 키 전송 대상도 바뀌므로 기존 자격 증명을 새 주소로 조용히 보내지 않는다.

## 14. 오류 화면과 복구 문구

| 상황 | 사용자 문구 | 우선 제공 행동 |
| --- | --- | --- |
| 키 거절 | 연결 정보가 거절되었습니다 | 키 다시 입력·서비스 확인 |
| 로그인 만료 | 로그인이 만료되었습니다 | 다시 로그인 |
| 모델 접근 불가 | 이 계정에서 선택한 모델을 사용할 수 없습니다 | 다른 모델 선택 |
| 요청 제한 | 지금은 요청을 처리할 수 없습니다 | 재시도·모델 선택 |
| 잔액 부족 확인됨 | 사용 가능한 잔액이 부족합니다 | 계정 관리 열기·모델 선택 |
| 네트워크 오류 | 서비스에 연결하지 못했습니다 | 다시 시도·진단 |
| 모델 목록 없음 | 모델 목록을 불러오지 못했습니다 | 재조회·검증된 목록·고급 입력 |
| 코딩 도구 호출 미지원 | 이 연결은 코드 실행 기능을 지원하지 않습니다 | 다른 모델 선택·분석용 사용 |
| 도구 어댑터 미지원 | 이 도구의 Talo 연결 기능은 준비 중입니다 | 다른 연결 방식 보기 |
| 보안 저장 실패 | 연결 정보를 저장하지 못했습니다 | 이번 실행에서 사용·저장 문제 확인 |
| 설정 파일 저장 실패 | 설정을 저장하지 못했습니다 | 다시 저장·진단 |

401이라는 코드만 보고 모델 미지원이나 키 오류로 단정하지 않는다. 서비스 응답과 실패 단계에 근거해 문구를 선택하고, 판단할 수 없으면 ‘연결에 실패했습니다’와 정제된 상세 정보를 제공한다. 잔액 부족도 서버 근거가 있을 때만 표시한다.

오류 상세는 접어서 제공한다. 키·토큰·전체 환경변수를 포함하지 않는다. 같은 요청을 무한 재시도하지 않고 진행 중에는 취소할 수 있게 한다.

## 15. 연결 상태 모델

개발팀은 다음 상태를 분리한다.

| 상태 | 의미 |
| --- | --- |
| draft | 서비스 또는 연결 방식 선택 중 |
| authenticating | 인증 진행 중 |
| authenticated | 인증만 확인됨 |
| loading_models | 모델 조회 중 |
| validating_model | 선택 모델·도구 호출 확인 중 |
| ready | 필요한 검증과 저장 완료 |
| limited | 대화 가능하나 코딩 도구 등 기능 제한 |
| needs_auth | 재인증 필요 |
| failed | 오류로 진행 불가 |
| cancelled | 사용자 취소 |

인증 비밀값, 임시 입력, 저장된 연결, 현재 활성 모델을 별도 상태로 관리한다. 새 연결이 ready가 되기 전 기존 활성 모델을 덮어쓰지 않는다. 실패한 초안을 연결 완료 목록에 넣지 않는다.

뒤로 가기·취소 시 사용자가 입력한 일반 설정은 보존할 수 있지만 인증 비밀값은 영구 로그에 남기지 않는다. 앱 종료 시 미완료 임시 자격 증명을 정리한다.

## 16. 구현 범위와 우선순위

### 1차: 현재 HTTP 연결의 사용성 개선

- `talo connect` 대화형 메뉴.
- 지원 서비스 프리셋과 주소 자동 설정.
- 키 붙여넣기·보안 저장 기본값.
- 모델 검색·선택.
- 인증·모델·도구 기능 검증.
- 연결 성공 후 저장·활성화.
- 실패 단계별 복구.
- `/model`에서 현재 연결 모델을 한 번에 선택.

현재 구현을 직접 확인한 후 기존 connect 내부 기능을 재사용할 수 있는지 판단한다. 플래그 명령을 화면 뒤에서 단순 문자열로 조립하기보다 검증·저장 서비스 함수를 공유한다.

### 2차: 로그인과 설치된 도구 연결

- 공식 지원되는 브라우저 로그인 어댑터.
- 코딩 도구별 설치·인증·실행 상태 확인.
- 외부 에이전트 연결과 세션 인계.
- 해당 연결이 지원될 때만 관련 메뉴 활성화.

### 3차: 설정 확장

- 로컬 AI 연결 화면.
- MCP 도구 관리.
- 스킬·기억 설정.
- 연결 내보내기·다른 기기로 이전할 때 비밀값 처리.

기술 설계의 독립 Talo 코어, 세션 보존, 수동 모델 전환 원칙은 유지한다. 브라우저 로그인과 외부 CLI 연결은 UI 작업만으로 완성되는 기능이 아니다.

## 17. 수용 기준

| 번호 | 시나리오 | 합격 기준 |
| --- | --- | --- |
| U01 | API 키를 보유한 첫 사용자 | 셸 환경변수·URL·모델 ID 수동 입력 없이 지원 서비스 연결 |
| U02 | 연결 후 시작 | validate·use 추가 명령 없이 작업 시작 |
| U03 | 모델 이름을 모름 | 목록 검색과 선택으로 설정 완료 |
| U04 | 잘못된 키 | 키 입력 단계에서 수정, 처음부터 재시작하지 않음 |
| U05 | 기존 연결 추가 | 추가 완료 전 현재 모델 유지 |
| U06 | 설정 중 취소 | 원래 작업과 연결 보존, 임시 비밀값 정리 |
| U07 | 모델 한도 초과 | 작업 저장, 수동 선택 제공, 자동 모델 전환 없음 |
| U08 | API_KEY만 발견 | 서비스 자동 단정·키 전송 없이 연결 대상 확인 |
| U09 | 설치됐지만 미지원인 도구 | 연결 완료로 오인할 수 없는 상태 표시 |
| U10 | 로그인 기능 없음 | 작동하지 않는 로그인 메뉴 노출 없음 |
| U11 | 목록만 조회 성공 | 코드 작업 검증 완료로 표시하지 않음 |
| U12 | 보안 저장 실패 | 평문 저장 없이 임시 사용 또는 해결 선택 |
| U13 | 대화 중 전환 | 세션·목표·파일 상태 인계, 진행 중 명령 중복 실행 없음 |
| U14 | 한국어 입력 | 조합·붙여넣기·검색·키보드 조작 정상 |
| U15 | 비대화형 실행 | 메뉴를 무한 대기하지 않고 필요한 입력을 구조화해 반환 |

핵심 사용성 목표는 ‘지원되는 서비스와 유효한 인증 수단을 가진 사용자가 기술 문서를 읽지 않고 연결을 마치는가’다. 연결 시간은 네트워크·외부 로그인에 영향을 받으므로 측정 전 30초 등으로 확약하지 않는다.

## 18. 다음 작업의 산출물

이 문서를 기준으로 연결 화면의 터미널 시안을 만든다. 실제 구현 단계에서는 Loc의 현재 Talo 소스와 지원 기능을 먼저 확인하고, S01·S03·S06·S08·S09·S10·S12·S13을 우선 구현한다.
